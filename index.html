Users & Scenarios

用户与使用场景

Code Agent

  • 用户：实验研发、代码审核人员
  • 任务：生成或修改实验代码
  • 价值：把自由生成转成带门禁的可复核流程

智能家居

  • 用户：家庭设备使用者
  • 任务：用一句话控制多个设备
  • 价值：降低操作成本并解释部分失败

RAG 问答

  • 用户：考研资料学习者
  • 任务：快速查询并核对知识
  • 价值：答案可回到来源片段
Problem

核心问题

上下文分散规则、类型、注册信息和业务约束分散在多个文件与协作角色中。
执行不可解释多设备联动只返回“成功”无法说明真实状态和失败范围。
答案缺少出处知识问答若没有来源引用，用户无法判断结论是否可信。
异常路径不足设备离线、检索无结果、模型置信不足时容易出现错误承诺。
效果口径模糊内部样本、线上效果和业务收益容易被混为一谈。
交付难复用缺少 PRD、规则、验收标准和容器配置时，项目难以复现。

Case 01 / Code Agent

理科实验 Code Agent 实习实践

产品决策

  • 优先建设规则路由与质量门禁，而不是先微调模型。
  • 根据实验域加载最小必要上下文，减少无关信息干扰。
  • 将类型检查、注册一致性和遗留问题纳入验收。
  • 最终合入仍由研发人员复核。

当前可验证资产

  • 17 份领域规则文档。
  • 注册一致性检查通过。
  • 10 条遗留提醒被保留。
  • 不展示缺少原始底表的收益百分比。
风险点产品规则验收方式
上下文选错按学科、实验域和任务类型选择规则集复核加载目录与任务归属
App / Engine 越界明确 UI 编排与实验引擎职责类型检查 + 人工 Review
组件遗漏注册把注册一致性设为质量门禁检查结果必须通过
历史问题被掩盖不因生成任务删除既有遗留提醒保留 10 条提醒并单独处理
Case 02 / Multi-Agent

智能家居多 Agent 协作系统

用户故事

用户说“我睡了”后，系统拆解为关床头灯、关净化器和调空调。若床头灯离线，返回“灯光未关闭，请检查插头；其余设备已就绪”，而不是把整次任务标记为失败。

设计原则

  • 配置外置，便于不同环境切换。
  • 设备域隔离，单设备故障不拖垮整套联动。
  • 异常可视化，用户能看到执行链和失败范围。
  • Docker 配置仅证明可容器化，不宣称生产部署。
1 个 Conductor识别意图、拆解、编排和聚合结果。
3 个设备 Agent空调、净化器和床头灯设备域。
1 个数据 Agent负责数据查询与场景辅助。
Case 03 / RAG

考研知识问答系统

产品体验

  • 答案优先，来源证据按需展开。
  • 用户可回到原始片段核对结论。
  • 支持流式回答、收藏和学习记录。
  • 无可靠来源时明确提示，而不是补全事实。

技术取舍

  • BM25 + 向量召回 + RRF 融合。
  • 当前数据规模下不优先使用 LoRA。
  • 暂无复杂关系检索需求，不使用 GraphRAG。
  • 容器配置用于复现，不代表线上全量效果。

知识切片1,263 条项目当前知识库规模
内部回归集36 道同源题只用于内部验证，不代表线上泛化

AI Tools in Practice

AI 工具使用心得

我不会把“使用过某个工具”当成能力证明。真正重要的是：它进入了哪个工作环节、减少了什么重复劳动，以及最终判断和风险由谁负责。

Claude Code｜规则与证据梳理

在 Code Agent 实践中，用于检索领域规则、梳理组件注册逻辑、对照检查结果和整理复核清单。AI 负责快速归纳和发现可能遗漏，我负责确认任务范围、判断 App / Engine 归属，并对最终交付结果负责。

Cursor｜多文件影响定位

用于在 PRD、类型约束、组件注册与实现文件之间定位改动影响，辅助理解陌生代码和生成重复性修改。对跨模块改动不直接接受自动补全，而是先核对依赖关系，再通过类型检查和人工 Review 验收。

Dify / Coze｜智能体原型验证

在进入完整研发前，先用低代码工作流验证输入字段、知识检索、引用返回与失败兜底是否成立。原型的目标是尽早暴露产品问题，而不是把平台演示包装成已经上线的业务系统。

工作阶段AI 工具承担的任务我保留的产品判断
需求梳理归纳访谈、文档和项目规则，形成问题清单判断哪些是真实痛点，哪些只是表面诉求
方案设计辅助比较 RAG、规则路由、Agent、微调等方案根据数据条件、风险和成本确定产品边界
研发协作定位相关文件、整理改动影响和生成检查清单确认职责归属、异常路径和是否允许自动执行
测试验收归类 BadCase、整理回归样本和检查结果统一数据口径，决定是否达到发布或交付标准

我的核心体会

AI 最擅长的是加快检索、归纳、初稿和重复检查；产品经理不能外包的是问题定义、优先级、风险边界与验收责任。使用 AI 越深入，我越重视保留原始证据、明确哪些内容只是建议，并让每个自动化步骤都有人工可接管的位置。

Acceptance

验收标准

模块验收标准
Code Agent规则按任务正确加载；注册检查通过；遗留提醒不被误删；最终结果可人工复核。
智能家居任务可拆解与下发；设备执行后读回；部分失败单独解释；高风险动作具备权限边界。
RAG答案与来源片段关联；无证据时不强答；内部回归结果带样本和版本口径。
原型展示桌面端与移动端画面清晰；不依赖外部 Figma 链接；支持站内放大。
数据表达区分内部验证、线上效果与业务收益；无底表指标不得包装为成果。

Review

项目复盘

三个项目让我确认了一件事：AI 产品经理的工作不是把模型能力写成功能列表，而是让用户任务、模型判断、规则约束、工具执行和人工复核形成闭环。当前最大的不足是业务结果底表不完整、部分测试仍是同源小样本；下一步优先补充任务级工时、异源评测和 BadCase 回流，而不是继续增加未经验证的功能。
